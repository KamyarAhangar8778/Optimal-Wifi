# PLAN — بهینه‌سازی WiFiServer (WiFiServer.h / WiFiServer.cpp)

> سند گام‌به‌گام بهینه‌سازی ماژول سرور TCP. تمرکز روی عملیات تکرارشونده (پولینگ available/hasClient و مسیر accept).

---

## ۱. وضعیت فعلی و خط مبنا

مسیرهای فراخوانی مکرر در استفاده‌ی واقعی:

| عملیات | فرکانس | هزینه‌ی فعلی |
|---|---|---|
| `available()` بدون کلاینت (poll) | هر بار loop | ۱ syscall غیرمسدودکننده (`lwip_accept` → EWOULDBLOCK) |
| `hasClient()` بدون کلاینت (poll) | هر بار loop | همان بالا |
| `available()` با کلاینت جدید | هر اتصال جدید | accept + **۲× setsockopt** (SO_KEEPALIVE + TCP_NODELAY) |
| `end()/close()/stop()` | یک‌بار | `lwip_close(-1)` بی‌گارد → syscall بیهوده با EBADF |

## ۲. گلوگاه‌ها و اصلاحات

1. **setsockopt زائد TCP_NODELAY:** وقتی `_noDelay == false` (پیش‌فرض)، ست‌کردن مقدار ۰ دقیقاً همون حالت پیش‌فرض lwip روی سوکت accept شده است → حذف کامل این syscall وقتی نیازی نیست. رفتار عینی سوکت تغییری نمی‌کند.
2. **SO_KEEPALIVE حفظ می‌شود** — تغییرش رفتار detect شدن قطع اتصال را عوض می‌کند؛ خارج از محدوده.
3. **گارد `sockfd >= 0` در end():** حذف close بی‌هدف روی سوکت بسته/هرگز باز نشده.
4. **مسیر poll دست نمی‌خورد** — accept غیرمسدودکننده از قبل حداقلی است؛ افزودن select() سنگین‌تر است نه سبک‌تر.

## ۳. انتظار واقعی (صادقانه)

- مسیر accept موفق: از ۳ syscall به ۲ → **~۳۳٪ کاهش syscall در لحظه‌ی اتصال کلاینت**
- مسیر poll بدون کلاینت: بدون تغییر (قبلاً بهینه)
- تأثیر روی بنچمارک‌های فعلی: جزئی (accept فقط ۱ بار در BENCH 3 رخ می‌دهد)
